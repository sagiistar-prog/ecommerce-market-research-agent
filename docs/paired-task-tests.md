# 从计划测试到核对结果

2026-09-19，仓库迭代 0.5.0。

## 用户问题与取舍

研究者已经从竞品材料提出假设，并选择了“计划测试”。之前的工作流止于评审导出，无法保存可执行的数值条件、导入观察或核对护栏。现在补上成对任务测试：同一参与者在可比较条件下分别操作基线与候选原型，研究者记录度量、判定条件、观察出处，再检查结果。

首个适用任务是“可拆内碗是否比一体式碗更容易清洗”。比较同容量、同材质、同污渍原型的完成用时，并记录拆装失败、遗漏清洗或洒落。项目附带数据全部是原创虚构练习，不是试用结果；示例的 3 对数据和 10 秒阈值只用于技术检查，不是推荐样本量或有价值改善的行业标准。

只支持非负连续度量的成对比较和一个二元护栏。没有用这一工具代替独立组 A/B 检验、统计功效分析、长期留存或营收评估。目标是让已选择的下一步可以执行和复核，避免再生成一份没有结果入口的测试计划。

## 网页流程

1. 分析材料，在 Hypotheses 导入假设，选择 Plan a test、填写理由并记录。先下载评审 JSON，它包含恢复所需的证据、假设和选择。
2. 打开 Tests。填写主指标、单位、基线与候选任务条件、指标方向、最小有用改善、最少独立观察对数、护栏失败定义与允许失败率。数据类型默认虚构练习，不冒充真实观察。
3. Record test plan 后下载计划。计划绑定证据、假设、提案编号及全部判定字段；修改任何条件会改变计划指纹。计划不能在已有结果上直接改阈值。另开计划时先保留之前的导出。
4. 下载 CSV 表头模板并填入观察。每行包含 `pair_id,baseline,candidate,guardrail_failed,source_ref`。匿名编号必须唯一；source_ref 用于定位观察记录，不自动抓取引用文件或网站。
5. 导入 CSV，查看结果并下载 JSON 与阅读版。重开网页时，先分析原材料、导入评审，再导入计划或结果 JSON。导入结果会从计划和原始 CSV 重新计算，不信任缓存的结论。

真实观察应先明确招募标准、任务条件、排除规则和顺序平衡。每一行对应一个独立观察对；工具能检查编号唯一，不能识别研究者把同一人的多次尝试伪装成不同人，也不能核验原始记录真实性。不要在公共仓库提交私人参与者信息。当前网页没有自动保存或云同步。

## 计算与决策边界

降低越好的指标，逐对改善为 baseline − candidate；提高越好的指标反向计算。主指标取**逐对差值的中位数**，不是两个组中位数之差。计算使用 Decimal，避免 0.1 这类浮点阈值产生边界误判。

护栏失败率的分母为本次导入的全部有效观察对，任意缺失数值、重复编号、非法失败标志、缺少出处或无穷值都会拒绝整个文件，不静默丢行。有限值允许 0 到 1,000,000,000；CSV 最多 200,000 字符与 1,000 行。

| 结果 | 条件 | 下一步含义 |
|---|---|---|
| Guardrail exceeded | 失败对数 / 总对数超过预设上限 | 先查失败原因，即使主要指标改善也不算达到全部条件 |
| Collect more paired observations | 护栏未超限，但样本少于计划 | 数据尚不足以按当前规则判断 |
| Improvement below target | 样本足够、护栏未超限，但改善低于阈值 | 当前数据未达到预设改善目标 |
| Recorded criteria met | 三项条件均满足，等于边界按达到处理 | 仅表示提交数据达到规则，需要研究者核查后决定下一步 |

任何结果都保留 `inference: descriptive_only` 和 `business_effect: not_established`。`synthetic_exercise` 与 `provided_unverified` 分开表达数据性质。计划指纹用于一致性检查，**不证明计划在观察前创建**，没有独立时间戳或预注册服务；若需要正式研究记录，应另行保存带时间证明的研究方案。

## 插件与命令行

计划字段契约为 [test-plan.schema.json](../schemas/test-plan.schema.json)。本地服务和 CLI 共用 [experiment.py](../scripts/experiment.py)，没有模型调用和网络抓取。网页表单与原生折叠组件沿用工作台风格，结果在前，计划和记录方法按需展开。

拿到网页导出的评审 JSON 后可先记录字段，再使用冻结的计划评估数据：

```bash
python scripts/review_test.py --review output/review.json --fields examples/pet-bowl-test-fields.json --output-dir output/test-plan
python scripts/review_test.py --review output/review.json --plan output/test-plan/plan.json --observations examples/pet-bowl-test-observations.csv --output-dir output/test-result
```

示例字段只适用于匹配的虚构宠物碗假设。真实任务应由研究者确定字段，不能复制示例阈值。输出目录必须不存在，保护旧结果。结果 JSON 包含计划、原始观察 CSV、观察文本哈希及重新计算的统计，Markdown 是阅读版。
